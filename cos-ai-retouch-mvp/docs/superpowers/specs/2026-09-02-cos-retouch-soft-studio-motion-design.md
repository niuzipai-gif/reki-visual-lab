# COS AI Retouch「柔光写真馆」视觉与动效设计规格

## 目标

将现有奶油色 COS 修图 MVP 从“表单卡片集合”提升为有专业写真工作室气质的工作台：照片是主角，工具退到辅助层，整体呈现可爱但克制、柔和但高级的感觉。

本次只调整前端视觉层、页面布局和交互动效，不改变上传、分析、计划确认、生成、结果对比、下载及当前开放模式的业务行为。

## 已确认方向

- 方向：B「柔光写真馆」
- 动效：1「微妙高级」
- 品牌：`AURA STUDIO`
- 中文副标题：`角色写真后期工作室`
- 主要用户：喜欢 COS、希望保留角色辨识度且不喜欢冷硬科技感的年轻女性用户

## 体验原则

1. **照片优先**：主要视觉焦点始终是原图或生成结果，控件不抢画面。
2. **工作室感**：布局像专业写真工作台，而不是后台管理表单。
3. **可爱高级**：使用雾粉、奶油白、香槟、深莓紫；避免霓虹、深色科技网格和过度装饰。
4. **每一步可理解**：用户始终知道当前处于上传、选择修图还是生成预览。
5. **动效服务反馈**：动效只说明进入、切换、处理和完成，不制造等待焦虑或视觉噪音。
6. **用户掌控**：不自动改变用户未确认的修图目标；原图始终可恢复和对比。

## 页面结构

### 桌面端

采用三段式工作台：

- **顶部品牌栏**：`AURA STUDIO`、中文副标题、当前步骤、照片隐私提示。
- **左侧步骤轨道**：固定展示 `上传照片 → 选择修图 → 生成预览`，用圆点、细连接线和状态颜色表达当前进度。
- **中央照片舞台**：占据最大空间，承载上传预览、分析原图、遮罩编辑和结果对比。
- **右侧控制栏**：仅显示当前步骤需要的操作。上传阶段展示引导和格式说明；分析阶段展示修图分组、力度和保护规则；结果阶段展示候选图和确认动作。

当前工作流组件继续复用现有 `UploadPanel`、`AnalysisPanel`、`MaskCanvas`、`ResultPanel` 和 `TaskProgress`，通过外层布局与样式重组，不复制业务状态。

### 移动端

- 左侧步骤轨道变为顶部横向进度条。
- 中央照片舞台先于控制栏显示。
- 控制栏变为舞台下方的纵向区域。
- 保持按钮可点击区域和现有键盘焦点可见性。

## 视觉系统

### 色彩

- 画布：奶油白与极浅雾粉渐变。
- 容器：暖白半透明表面，配合低对比度莓紫边线。
- 主强调：柔和莓紫，用于主按钮、当前步骤、识别高亮和滑块。
- 辅助强调：香槟金，用于细线、光晕和结果完成提示。
- 状态：沿用现有绿色成功、琥珀提醒、红色错误语义，保证信息可读性。

### 字体与层级

- 品牌与大标题可使用衬线风格，形成写真杂志气质。
- 正文、表单、状态和错误信息继续使用清晰的无衬线字体。
- 标题不超过两行；说明文案保持短句，避免产品术语堆叠。

### 表面与间距

- 减少嵌套白卡；照片舞台使用最大层级，控制栏使用更轻的表面。
- 卡片圆角统一为中等圆角，避免每个元素都像独立浮层。
- 阴影使用大范围、低透明度的暖色阴影，不使用黑色硬阴影。
- 保持当前桌面、平板和手机断点，优先确保照片舞台不会被窄栏压缩。

## 动效规格

### 入场

- 品牌栏、步骤轨道、照片舞台和控制栏按顺序淡入并上移 6–12px。
- 单次入场总时长不超过 600ms，使用柔和 ease-out。

### 上传与分析

- 上传区域在照片选择后平滑过渡为照片舞台，避免整页跳变。
- 照片使用轻微缩放和透明度显影，不使用大幅旋转。
- 分析识别完成时，只在人物区域显示一次低强度光晕扫过；识别框保持静态，避免持续闪烁。

### 步骤切换与结果

- 控制栏横向滑入、旧内容淡出，中央照片舞台保持稳定，减少空间跳动。
- 生成候选图从下方轻微错位浮现；候选卡 hover 只上浮 2–4px。
- 主按钮提供轻微呼吸高光和按压反馈，不使用连续弹跳。

### 可访问性

- 所有动效必须在 `prefers-reduced-motion: reduce` 下缩短为近乎瞬时或关闭。
- 动效不得作为唯一状态提示；进度、成功、错误仍需有文字和语义状态。
- 不降低现有 focus-visible、表单标签、按钮名称和遮罩画布键盘可用性。

## 组件边界

- `App`：保留工作流状态和步骤判断，只承担新的页面壳层 class/布局结构。
- `AppHeader` 或现有 header 区域：承载品牌、步骤上下文和隐私提示。
- `WorkflowRail` 或现有 aside：承载桌面步骤轨道，移动端变为顶部进度条。
- 现有业务面板：只增加语义 class 和必要的展示层容器，不重写 API 调用、任务状态和表单逻辑。
- `styles.css`：集中管理颜色 token、布局、状态和动效 keyframes；避免在组件中散落不可复用的视觉常量。

若实现中发现单个组件为了布局承担过多职责，只做服务于本设计的最小拆分，不进行无关重构。

## 错误与降级

- API 失败、任务过期、生成失败继续使用现有 `TaskProgress` 和用户安全错误文案。
- 动效加载失败或浏览器不支持时，静态布局必须完整可用。
- 移动端空间不足时优先保留照片、当前步骤和主要操作，次要说明可以收起但不能删除错误信息。

## 验收标准

- 首屏直接进入开放模式的上传工作台，视觉上不再像邀请码或后台表单入口。
- 桌面端明确呈现“左步骤轨道＋中央照片舞台＋右控制栏”。
- 移动端照片在控制项之前，步骤轨道变为顶部进度条。
- 上传、分析、切换、生成结果各有一次克制且可理解的动效。
- `prefers-reduced-motion` 下无持续动画或明显位移。
- 现有前端测试、构建和后端测试全部通过；不改变任务 API 合同和当前无 token 开放行为。
