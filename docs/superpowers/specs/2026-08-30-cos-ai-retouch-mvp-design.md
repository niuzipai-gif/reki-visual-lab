# COS AI 修图工具 MVP 设计规格

日期：2026-08-30
状态：待用户审阅
工作名称：COS 后期修图台（暂定）

## 1. 产品定义

这是一个面向 COS 摄影者、COSER 和后期修图师的单图 AI 修图工作台。第一版不追求替代 Photoshop，而是把最费时间、最容易反复返工的两个环节产品化：

1. 自然精修：脸部、皮肤、发丝、服装细节、轻微体型和光影统一。
2. 局部结构修复：手脚、姿态连接、衣服与身体的衔接、道具接触关系。

产品原则是“先分析、再确认、后生成”，而不是让模型直接重绘整张照片。

## 2. MVP 边界

### 包含

- 邀请链接访问，无注册和复杂账户系统。
- 单次只处理一张照片。
- JPG/PNG 上传，原图不被覆盖。
- AI 自动分析人物、服装、头发、手脚、道具和背景。
- 自动生成建议区域和蒙版，用户可以用画笔添加/擦除。
- 两种目标：自然精修、结构修复；可同时使用。
- 每个任务最多生成两个候选版本。
- 前后对比、版本回退、重新生成和下载。
- 保存本次任务的处理模块、参数、提示词和结果地址。

### 暂不包含

- 批量处理、多人物批量一致性。
- 完整 PSD 分层和 Photoshop 插件。
- ComfyUI/本地模型/GPU 部署。
- 用户长期素材库、社交分享和付费会员。
- 全自动大幅换脸、换服装和全身姿势重构。

## 3. 核心用户流程

```text
邀请链接
  → 上传照片
  → AI 分析
  → 选择“自然精修 / 结构修复 / 两者结合”
  → 查看问题卡片
  → 确认处理区域与强度
  → 生成 1–2 个局部版本
  → 自动质量检查
  → 前后对比
  → 接受、回退或继续修改
  → 下载结果
```

### 页面 1：上传页

- 显示隐私说明：照片用于本次任务，默认 24 小时后清理。
- 上传区域显示文件类型、大小和预览。
- 上传成功后进入分析，不提前要求用户写提示词。

### 页面 2：分析页

画布左侧显示照片，右侧显示问题卡片。分析只提出建议，不直接改图。卡片至少包括：

- 脸部：瑕疵、肤色、眼神光、妆容边缘。
- 头发：断发、毛躁、边缘缺失、发丝方向。
- 服装：褶皱、污渍、材质和身体连接。
- 身体：手脚异常、比例风险、姿态连接。
- 背景：液化或重绘可能造成的变形区域。
- 光影：局部亮度、色温和原始光源方向。

每张卡片提供“启用/关闭”和风险提示，不默认启用所有模块。

### 页面 3：区域与参数页

- 自动蒙版可见，并支持画笔添加、擦除、羽化和放大检查。
- 默认保护脸部、角色服装设计、构图、主姿势和背景结构。
- 强度采用“自然、标准、明显”三级，底层仍保存 0–100 数值。
- 结构修复必须要求用户确认具体区域，避免模型重绘整个人物。

### 页面 4：结果页

- 提供拖动式前后对比和局部放大。
- 明确标出“本次修改区域”。
- 显示质量检查结果：脸部、手脚、服装、背景、光影五类。
- 检查有疑点时，不阻止用户查看，但将结果标记为“建议复核”。
- 提供“保留此版本”“重新生成”“恢复原图”。

## 4. 人物保护和 AI 处理规则

每个任务都生成一份结构化处理计划，内部字段分为：

- `preserve`：必须保持的内容，如身份、脸、构图、服装设计、姿势。
- `regions`：实际处理区域及蒙版来源。
- `operations`：修脸、发丝、服装或结构修复等操作。
- `intensity`：模块强度。
- `integration`：光影、透视、景深和噪点融合要求。
- `validation`：生成后要检查的区域。

JSON/提示词是内部中间格式，普通用户不需要看到。后续可以增加“复制提示词”高级入口，但不能让提示词编辑成为主流程。

### 默认硬约束

- 不改变人物身份和面部主要特征。
- 不改变主姿势、相机视角和构图。
- 不改变角色服装的核心设计。
- 不让液化或局部重绘造成背景弯曲。
- 所有新增或修复内容匹配照片原有光源、透视、景深和噪点。
- 低置信度区域要求用户手动确认，不盲目生成。

## 5. 技术架构

### 部署分工

- 前端：React/Vite 静态应用。小规模测试可先部署 GitHub Pages；若面向公开商业 SaaS，迁移到 Render Static Site、Cloudflare Pages 或其他合规静态托管。
- API：Render Web Service，提供任务创建、上传签名、分析、生成、状态查询和下载授权。
- 图片存储：S3 兼容对象存储，例如 Cloudflare R2、S3 或 Supabase Storage。
- 元数据：Render Postgres 或外部托管数据库，只保存任务状态、参数和对象存储地址。
- 图像模型：外部图像编辑 API，通过 Render 的服务端密钥调用。
- 异步任务：MVP 使用 Render API + 状态轮询；任务量增加后再接 Render Background Worker 和队列。

Render 文件系统默认是临时的，因此原图和结果图不得写在 Render 本地目录。GitHub Pages 前端也不得放置任何模型 API 密钥。

### 数据流

```text
浏览器
  → Render API 创建 task
  → Render 返回对象存储 signed URL
  → 浏览器直传原图
  → Render 分析图像并保存 analysis
  → 用户确认 plan 与 mask
  → Render 调用外部图像模型
  → 结果写入对象存储
  → 浏览器轮询 task 状态
  → Render 返回短时下载 URL
```

### 任务状态

`created → uploading → analyzing → awaiting_confirmation → generating → validating → succeeded`

异常状态为 `failed` 或 `expired`。每个状态都必须有用户可理解的说明，不能只显示“请求失败”。

## 6. 失败处理与成本控制

- 上传失败：允许重新上传，不创建重复任务。
- 分析失败：保留原图，提供重新分析；不自动进入生成。
- 蒙版为空或过大：提示用户重新确认区域。
- 模型超时：任务转为失败，提供重试；单任务最多自动重试 2 次。
- 质量检查有疑点：返回结果但标记复核区域，让用户决定保留或重做。
- 外部 API 配额/余额不足：显示服务暂不可用，不泄露服务端密钥或详细内部错误。
- 原图、蒙版和结果默认 24 小时后清理，任务记录只保留必要元数据。
- 单任务最多两个候选结果，不提供批量生成。

## 7. MVP 验收标准

### 功能验收

- 用户可以在无注册情况下通过邀请链接完成一次单图处理。
- 任务全程不需要用户手写专业提示词。
- 用户能够看到 AI 建议，并在生成前确认区域和强度。
- 生成结果可以前后对比、回退和下载。
- 原图始终可恢复，失败不会覆盖原图。
- 任务状态在刷新页面后仍可恢复，至少保留到任务过期。

### 质量验收

使用至少 20 张不同类型的 COS 照片进行人工评审，覆盖半身、全身、假发、盔甲/复杂服装、室内和夜景。每张照片重点检查：

- 人脸身份是否保持。
- 主姿势和构图是否保持。
- 手脚及服装连接是否比原图更自然。
- 背景是否出现明显变形。
- 修图是否与原始光影和噪点融合。

第一版不是追求每张图一次成功，而是保证用户能看见问题、控制区域、比较版本并快速回退。

### 用户成功标准

没有专业提示词经验的用户，能够在 10 分钟内完成一次“自然精修 + 一个局部结构修复”，并获得一张自己愿意继续精修或发布的预览图。

## 8. 后续演进顺序

1. 增加对话式微调，例如“左手再自然一点，其余不变”。
2. 增加同一组片子的风格和人物一致性。
3. 增加 PSD 分层导出和 Photoshop/ComfyUI 适配。
4. 增加批量任务、历史作品和团队协作。
5. 评估本地模型或 GPU worker，降低外部 API 依赖。
