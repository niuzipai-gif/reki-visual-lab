# Reki AI 风格建议与可靠对比工作台设计

## 目标

修复原图对比在真实图片导入场景下的失效问题，并将 AI 功能从“仅本机关键点扫描”扩展为面向 coser 的图片风格分析与一键应用。品牌图标统一使用用户提供的角色图，工作台背景采用已选定的 B「柔雾奶油」方向，同时补充图层“一键清除全部”操作。

## 已确认的体验

1. **原图对比**
   - 顶部按钮在“编辑预览 / 原始导入图片”之间切换。
   - 切换时保留标记、选择、撤销/重做历史和当前项目。
   - 原始图片必须来自当前项目保存的 `originalFile`，不能只依赖已经处理过的预览资源。
   - 对 URL、`ImageBitmap`、`HTMLImageElement` 和 IndexedDB 恢复的图片都要覆盖测试。

2. **品牌与视觉**
   - `reki-mark.svg`、favicon、网页标签图标和顶部品牌锁定使用用户提供的角色图，不再使用截图或替代图案。
   - 工作台采用 B「柔雾奶油」：米杏色玻璃层、深色编辑底、红色标记和低对比装饰背景。
   - 装饰背景不得覆盖画布、控制点或交互层；移动端降低透明度与资源尺寸。

3. **AI 风格建议**
   - 输入：当前图片的受控分析数据（尺寸、亮度/对比度/饱和度、主体区域与可选的关键点结果），以及用户选择的风格偏好。
   - AI 输出结构化 JSON，不直接返回任意代码或 CSS。输出包含 3 个方案，每个方案包含名称、风格说明、滤镜参数、标记模板、密度、标签策略和风险提示。
   - UI 先展示建议，用户点击某个方案的“应用”后，统一通过 reducer 一次性提交滤镜与图层变更；一次应用可撤销。
   - 如果远端 AI 不可用，保留本机确定性分析与内置推荐方案，功能仍可用，并明确提示“离线建议”。
   - API Key 只从部署环境变量读取，前端不得打包、硬编码或提交到仓库。浏览器端调用需经过受保护的服务端/worker 代理，并设置超时、取消、错误分类和最小化图片数据策略。

4. **图层管理**
   - 图层面板增加“清除全部图层”按钮。
   - 清除前提供明确确认；确认后一次性移除所有图层，进入撤销历史。
   - 空图层状态提供可访问的提示，不影响继续添加标记。

## 组件与数据流

- `BackgroundLayer` 负责原图与编辑预览的可靠绘制，显式区分 `originalFile`、工作预览和 URL 资源，并在源切换时清空缓存。
- `AiStylePanel` 负责分析请求、结构化结果校验、建议卡片和应用动作；`styleAdvisor` 负责本机特征提取、远端适配和离线回退。
- `stylePresets` 将 AI 建议映射为现有滤镜与标记模板，生成 reducer 可接受的单次 `style/apply` 操作。
- `LayersPanel` 负责确认、清除全部和撤销提示；实际状态修改仍由 editor reducer 完成。
- 品牌资源放在 `public/brand/`，只保留经过尺寸压缩的用户图标版本和 favicon 版本。

## 错误与隐私

- 原图解码失败：保留当前预览，显示“原图不可用，请重新导入”，不清空图层。
- AI 请求超时、鉴权失败、限流或返回格式错误：显示可理解的状态，自动切换离线建议，不泄露 key 或原始响应。
- 图片默认不持久化到远端；远端分析前明确标示上传状态，限制图片尺寸并在请求完成后释放临时资源。

## 验证标准

- 单元测试覆盖原图源切换、过滤器缓存失效、AI JSON 校验/离线回退、建议应用的单次撤销、清除全部图层确认。
- 组件测试覆盖真实导入后切换“原图对比”、三种 AI 建议卡片、一键应用、错误状态和清除全部图层。
- `npm test`、`npm run build`、`npm run test:sites` 与 `git diff --check` 全部通过。
- 本地与公开部署各完成一次手动冒烟：导入图片、切换原图、应用一个 AI 建议、清除图层、撤销恢复。
